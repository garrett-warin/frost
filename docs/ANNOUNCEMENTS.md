# Admin Console and announcements

Open Frost's three-dot menu and choose **Admin Console**. It opens a separate CloudFront HTTPS origin, isolated from websites opened inside Frost. The first owner must use the private one-time enrollment link, scan its QR code with an authenticator app, and enter a valid six-digit code. After enrollment, only authenticator login is accepted; the setup link cannot enroll a replacement authenticator.

Enter a fresh TOTP code to unlock the console. Codes use SHA-1, six digits and 30-second periods with one adjacent time step of tolerance. Each accepted code can be used once. Five authentication attempts per minute are allowed globally using atomic DynamoDB updates. Random bearer sessions last 15 minutes, remain only in the admin tab's memory, and are revoked on logout; local locking still works if the network fails. Keep the authenticator backup in your own password manager. Recovery requires owner AWS access to reset enrollment deliberately.

The console lets you publish up to 1,000 characters or remove the banner. Text is rendered literally under **Developer Announcement**, beside an inline SVG claw hammer. The banner is hidden when no message is published. Frost polls every minute and the server caches reads for 15 seconds; changes can take about 75 seconds to appear.

CloudFront uses an IAM-protected Lambda Function URL with Origin Access Control. Only that distribution can invoke the origin. Caching is disabled for admin responses. State, replay protection, rate limits, sessions, and announcement text live in one encrypted DynamoDB table. The Lambda role can access only that table. Neither AWS credentials nor the TOTP secret enter the Frost browser shell. POST requests require the exact admin Origin; no credentials are shared through CORS, cookies, localStorage, or the proxy origin.

Deployment sources: admin/stack.json, admin/handler.mjs, admin/service.mjs, admin/admin.js and admin/deploy.sh. Build with `node scripts/build-admin.mjs` and package with `node scripts/package-admin.mjs`. The CloudShell script deploys only the frost-admin stack in us-east-1 and a private artifact bucket. It stores an owner-only setup link in ~/.frost-admin-enrollment-url until enrollment is complete; remove that file and ~/.frost-admin-setup after confirmed enrollment. The table is retained on stack deletion to avoid accidental loss. The original distribution now serves the main Frost browser from Fly; a second distribution serves only the admin Lambda. Main-site traffic forwards WebSocket headers and query strings without caching. Set FROST_EDGE_ORIGIN to the main CloudFront origin and FROST_ADMIN_ORIGIN to AdminDomain from the stack outputs.

The earlier `npm run announce` environment-based approach is superseded once FROST_ADMIN_ORIGIN is configured. Hosted publishing uses the console and shared database.
